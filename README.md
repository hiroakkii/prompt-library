# プロンプトライブラリ

画像生成AI（NovelAI / PixAI）で使うプロンプトを管理し、「シチュエーション × キャラ」で組み立てるための、1ファイル完結のWebアプリです。

`index.html` をブラウザで開くだけで動きます（ビルド不要）。

## 主な機能

| 画面 | できること |
|---|---|
| プロンプト | ポジ・ネガ・シチュエーション・キャラの一覧。検索（スペース区切りでAND）・並べ替え・お気に入り・使用回数・複数選択・一括削除（元に戻せる） |
| 絞り込み | 種別（ポジ／ネガ／シチュ／キャラ）、カテゴリ（複数選択）、タグ（複数選択・「すべて含む／いずれか」切り替え） |
| 組み立て | 一覧で選んだシチュエーションとキャラを表示・調整し、NovelAI / PixAI 用に出力 |
| 設定 | NovelAIの重み書式・刻み・区切り文字、人数タグの自動付与、重複タグの除去、括弧のエスケープ、カテゴリの名前変更・削除、全置換前の状態への復元 |

### 画面の配置

- スマホ：画面下のタブで「プロンプト」「絞り込み」「組み立て」を切り替えます。
- PC（幅1100px以上）：左に一覧（または絞り込み）、右に組み立てを常に並べて表示します。
- 色は種別を表します（ポジ＝藍、ネガ＝紅、シチュエーション＝青緑、キャラ＝琥珀）。一覧の左端の色帯、チップ、組み立ての各ブロックの上端で同じ色を使います。
- 画面の文字は Google Fonts の Zen Kaku Gothic New を使います。読み込めない環境では端末の標準フォントで表示します。

## 登録と組み立ての考え方

「新規追加」で、次の4種類を登録できます。どれも同じ一覧に並び、検索・絞り込み・お気に入りが使えます。

| 種別 | 登録する内容 | 一覧でクリックすると |
|---|---|---|
| ポジ / ネガ | 1つのプロンプト（タグか文章） | 組み立て中の「追加先」に入る（ネガは常にネガティブへ） |
| シチュエーション | ベース（ポジ）とネガティブを同時に | 組み立てタブに読み込む |
| キャラ | 性別・外見・服装 | 選択中のキャラ枠に入る（枠が無ければ作る） |

登録したあとでも、編集画面で種別を変えられます（種別の変換）。

- 元の内容は新しい種別の欄に移します（例：ポジ → シチュエーションならベースへ、ネガ → シチュエーションならネガティブへ、ポジ → キャラなら外見へ）。
- 引き継げない内容（シチュエーション → ポジのときのネガティブ、キャラ枠ごとの状態、性別など）がある場合や、その項目を使っているチップとのつながりが切れる場合は、保存前に1回だけ警告します。チップの内容自体は残ります。
- 変換は直後なら「元に戻す」で取り消せます。ポジ ⇔ ネガの切り替えは警告なしです。

シチュエーションとキャラの入力欄では、1行ごとにカンマ区切りのタグか文章を書きます（文章は文末を `.` で終える）。重みは `(tag:1.2)` で書けます。

```
組み立て ＝ シチュエーション 1つ ＋ キャラ（NovelAI 最大22人／PixAI 最大6人）
```

- シチュエーションには、キャラそのものではなく「そのシーンでのキャラの状態」を枠ごとに登録できます（新規追加・編集画面の「キャラ枠ごとの状態」）。
  - 各枠に、状態（表情・ポーズ・動作タグなど）と想定の性別を書きます。
  - 一覧でシチュエーションを読み込むと、登録した枠の数だけ空のキャラ枠が用意されます。あとは一覧でキャラをクリックして入れるだけです。
  - キャラが未選択の枠も、状態だけで出力されます（NovelAI では「キャラN（未選択）」の欄）。人数タグは想定の性別から作ります。キャラを入れたときはキャラの性別を優先します。
  - 未選択の枠を状態だけで出力しているときは、出力欄の上に警告を出し、該当する出力欄に「キャラ未選択を含む」の印を付けます。その欄をコピーしたときや .txt で保存したときも、未選択の枠があることを知らせます。
  - 組み立てタブで枠の × を押すと、その枠の状態も外れ、以降の枠が1つずつ前に詰まります（「元に戻す」で登録内容に戻せます）。
- 組み立てタブに読み込んだ内容は**作業用のコピー**です。重みの変更や項目の追加はその場限りで、登録内容は変わりません。
  - 変更があると「未保存の変更」と表示されます。
  - 「上書き保存」：登録内容を、いまの組み立て内容で置き換えます（直後なら元に戻せます）。
  - 「別件として保存」：新しいシチュエーション（キャラ）として登録します。
  - 「元に戻す」：登録内容を読み直します。
  - 未保存の変更があるときに別のシチュエーションやキャラを読み込むと、破棄してよいか確認します。
- シチュエーションを固定したまま、キャラ枠のキャラだけを入れ替えられます。
- 「シチュエーションとキャラを一括削除」で、組み立て中のシチュエーションとキャラ枠をまとめて外せます（確認は1回。一覧の登録内容は消えません）。
- 「キャラ枠ごとの状態」は**枠の番号**に付きます。`source#hug` をキャラ1の枠に、`target#hug` をキャラ2の枠に入れておけば、誰を入れても役割は変わりません。
- シチュエーションで「キャラの服装を使わない」をオンにすると、キャラの服装を出さずに、シチュエーション側の服装だけを使えます。
- チップは長押し（PCはドラッグ）で、並べ替えや、別の欄（ベース⇔外見など）への移動ができます。

### 出力

| 出力先 | 出力される欄 | 重みの書式 |
|---|---|---|
| NovelAI | ベースプロンプト ／ キャラ1〜n ／ 除外したい要素 | `1.20::word::`（または括弧の重ね `{word}`） |
| PixAI | プロンプト（ベース → キャラ1 → キャラ2 …を1本に。区切り文字か改行段落でつなぐ） ／ ネガティブ | `(word:1.20)` |

- 人数タグの自動付与（初期値オン）：ベースの先頭に、選んだキャラの性別から `2girls, 1boy` などを付けます。このとき、ベースにもともとある人数タグは置き換えます。NovelAIでは、キャラ欄の先頭にも `girl` / `boy` を付けます。性別が「その他」のキャラは数えません。
- PixAIでは全キャラのタグが1本にまとまるため、どのタグがどのキャラに効くかは指定できません。
- キャラ数の上限：NovelAI は V5 の公式上限に合わせて22人です（実際に安定する人数はもっと少ないことがあります）。PixAI は1本にまとまるので6人までで、それより多い枠があるときは先頭6人だけ出力します。
- トークン数は概算です（実際のトークナイザーとは多少ずれます）。

### タグと文章（自然言語）

PixAI Tsubaki.3 のように文章での入力が向いているモデルに対応するため、ライブラリの各項目を「文章」として登録できます（編集画面のチェック、または Excel の `形式` 列に「文章」と書く）。

- 文章の項目はカンマで分割しないので、重複除去・括弧のエスケープ・人数タグの置き換えの対象になりません。
- 文末（`.` など）のあとにはカンマを付けず、スペースでつなぎます。
- 設定「PixAI でのベースとキャラのつなぎ方」を「改行で段落に分ける」にすると、ベースとキャラごとの描写が段落に分かれます。
- タグと文章は混ぜて使えます（例：先頭にタグ、続けて場面の描写）。

## 取り込み・書き出し

- **Excel / CSV**：1行目の見出し（`カテゴリ` `表示名` `プロンプト` `タグ` `メモ` `種別` `形式` `ネガティブ` `服装` `性別`）で列を判定します。見出しが無い場合は、先頭7列（カテゴリ〜形式）の順で読み取ります。タグは `,` か `、` で区切ります。
  - `種別` が「シチュ」の行は、`プロンプト` をベース、`ネガティブ` をネガティブとして読みます。
  - `種別` が「キャラ」の行は、`プロンプト` を外見、`服装` を服装、`性別` を性別として読みます。
  - キャラ枠ごとの状態と「服装を使わない」の設定は、Excel / CSV には含まれません（JSON には含まれます）。
- **JSON**：バックアップの保存・復元用です（形式 v3）。全置換すると、組み立て中の状態も復元されます。旧形式（v1 / v2）のバックアップも読み込めます。その場合、シチュエーションとキャラは一覧の項目に変換されます。
- 「全置換」は直後のトーストから元に戻せます。設定画面の「全置換する前の状態に戻す」からも復元できます。
- Excel機能（SheetJS）は、取り込み・書き出しをしたときに読み込みます。まず公式CDNの最新版を読み込み、読み込めない環境（Claudeアプリ内など）では jsDelivr の 0.18.5 を SRI 付きで使います。

## データの保存先

起動した環境に応じて、自動で選びます。

1. Claudeアプリ内の保存領域（`window.storage`）
2. ブラウザの localStorage
3. どちらも使えない場合はメモリのみ（画面上部に警告が出ます）

念のため、定期的に「書き出し」→「JSON バックアップを保存」で手元にバックアップを残してください。

## 開発メモ

- 変更は `index.html` を直接編集し、内容が分かるコミットメッセージを付けてコミットしてください（GitHub上で「削除→アップロード」を繰り返すと、差分の履歴が追えなくなります）。
- 保存キー：`plib.library.v1`（一覧の全項目・カテゴリ）、`plib.compose.v3`（組み立て中の作業用コピー）、`plib.config.v1`（設定）、`plib.prereplace.v1`（全置換前のバックアップ）、`plib.premigrate.v3`（形式移行前のデータ）
- 旧形式のデータ（`plib.compose.v2` のシチュエーション・キャラ、`plib.memos.v1` のメモ欄タブ）は、`plib.compose.v3` が無い場合だけ、初回起動時に一覧の項目へ移します。旧データは消さずに残し、移行前のデータは設定画面からJSONで保存できます。
