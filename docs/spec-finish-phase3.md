# 仕様書：仕上げ（第3回）

設計：Fable 5.2 ／ 実装：Sonnet 5.5。この文書だけを読んで実装できるように書いています。前提は第1回（`docs/spec-gloss-phase1.md`、訳の辞書）と第2回（`docs/spec-mobile-phase2.md`、スマホの操作）が実装済みであること。

## 背景と目的

- 利用者は iPhone でこのアプリ（`index.html` 1ファイル）を使います。プロンプトは Muse（AI エージェント）に JSON で作ってもらい、貼り付けて取り込みます。
- 残っている使いにくさは次の4つです。
  1. 組み立てタブが縦に長く、見たい場所までスクロールが多い。
  2. 編集画面（新規追加・編集）がスマホでは小さい窓の中の長いスクロールになり、保存ボタンが遠い。
  3. Muse に「このシチュエーションを直して」と頼んで戻ってきた JSON を取り込むと、同じ名前の項目が2つになる（上書きできない）。
  4. データは端末の中にしかないのに、バックアップを取る習慣を助ける仕組みがない。

## 1. 組み立てタブの折りたたみ

- 「シチュエーション」「キャラ」「出力」の3つのブロック（`.blk.sit` / `.blk.char` / `.blk.out`）を、それぞれ折りたためるようにする。
- 各ブロックの見出し行（`.bhead` の先頭）の左端に、開閉ボタン（▾ 開いている／▸ 閉じている、44×44px の押せる範囲、`aria-expanded` 付き）を置く。見出しの文字（「シチュエーション」など）を押しても開閉する。見出し行の中の他のボタン（「一覧から選ぶ」「＋キャラ枠」「まとめてコピー」など）は今までどおり動き、開閉しない。
- 閉じているときは、見出し行と**1行の要約**だけを出す。要約はあふれたら `…`。
  - シチュエーション：`名前 ／ ベース N・ネガ N`（未保存の変更があれば、今の「未保存の変更」の印も残す）
  - キャラ：`ミナ、レン`（入っているキャラの名前。未選択の枠は「未選択」。0枠なら「なし」）
  - 出力：`3 欄`（中身のある出力欄の数。全部空なら「なし」）
- 開閉の状態は `S.cfg.fold = {sit:false, char:false, out:false}`（true が閉じている）に保存する。初期値はすべて開いている。
- 閉じているブロックに一覧から項目が追加されたときは、閉じたまま要約の数が変わる（自動では開かない）。
- 順番コピーのバーは、出力ブロックを閉じていても今までどおり使える。
- PC・スマホの両方で有効。

## 2. 編集画面（`#mEdit`）

### スマホ（幅720px以下）：全画面のシート
- 画面いっぱいに表示する（`inset:0`、角丸なし、背景の暗転なし）。
- 上端に固定の見出し帯：左に題名（今の `#edTitle`）、右に「閉じる」（44×44px、キャンセルと同じ動き）。
- 下端に固定のボタン帯：「キャンセル」と「保存」（`btn go`、どちらも高さ44px以上。保存を広く）。`env(safe-area-inset-bottom)` の分の余白を足す。
- 中身（入力欄）は、見出し帯とボタン帯の間でスクロールする。キーボードが出ても保存ボタンが押せること（`100dvh` を使う）。
- 第2回で作った丸い「＋」ボタンや下のタブバーは、このシートの下に隠れること。

### PC（幅721px以上）
- 今の中央のモーダルのまま。ただしボタン（キャンセル・保存）は、モーダルの下端に固定して常に見えるようにする（中身だけがスクロール）。

### キャラ枠の折りたたみ（PC・スマホ共通）
- シチュエーションの「キャラ枠ごとの状態」の各枠（`.eslot`）を折りたためるようにする。
- 枠の見出し（「キャラ1」の行）を押すと開閉。閉じているときは1行の要約：`想定：女性 ／ 状態 2・表情 1・セリフあり`（入っているものだけ）。
- 編集画面を開いたとき：枠が3つ以上あれば、すべて閉じた状態で出す。2つ以下なら開いた状態。「＋枠を追加」で足した枠は開いた状態。
- 閉じていても、入力した内容は保存時に読み取れること（`readESlots()` が閉じた枠の値も返す。要素は消さずに隠す）。

## 3. Muse との修正の往復

### 3-1. 「Muse 用にコピー」
- 編集画面で、**登録済みの項目を編集しているとき**だけ、ボタン帯の左端に「Muse 用にコピー」（`btn`）を出す。新規追加のときは出さない。
- 押すと、**いま登録されている内容**（編集画面で入力途中の内容ではない）を、次の形でクリップボードに入れる。トースト：「Muse 用にコピーしました。Muse に貼って、直したい内容を伝えてください」
  ```
  次の JSON は、画像生成AI用プロンプトの登録データです。
  下の「直したい内容」に沿って直し、同じ形の JSON だけを返してください。
  "name" は変えないでください（同じ名前の項目を上書きするためです）。
  タグは1つずつ {"text":"英語のタグ","ja":"日本語の訳"} に分けてください。

  直したい内容：（ここに書いてください）

  <JSON>
  ```
- `<JSON>` は `{"v":3,"prompts":[<項目>]}` を `JSON.stringify(…, null, 1)` したもの。項目に入れるのは次だけ（`id`・`cid`・`pid`・`uses`・`fav`・`created`・`text`（シチュエーション・キャラの要約）は入れない）。
  - 共通：`kind`、`name`、`cat`、`tags`、`note`（空のものは省く）
  - ポジ・ネガ・表情：`text`、`nl`（true のときだけ）、`ja`（`glossText(text,nl)` に訳が1つでもあれば、その文字列）
  - シチュエーション：`folder`・`order`（フォルダがあるときだけ）、`base`、`neg`、`slots`、`slotFaces`、`slotSex`、`slotLines`、`slotBubbles`（すべて true なら省く）、`noOutfit`（true のときだけ）
  - キャラ：`sex`、`look`、`outfit`
  - チップは `{"text":…,"ja":…,"w":…,"nl":true}`。`ja` は辞書に訳があるときだけ（複数タグのチップは `glossText` の結果を入れてよい。訳がそろっていなければ省く）。`w` は 1 以外のときだけ。`nl` は true のときだけ。

### 3-2. 同じ名前の項目を上書きして取り込む
対象は「取り込む項目を選ぶ」画面（`openImport` / `renderImp` / `applyImport`）の「選んだ項目を追加」。「全置換」は今のまま。

- 取り込む行のうち、**種別と名前が同じ項目がすでに登録されている**もの（内容まで同じで「登録済み」になる行は除く）を「同じ名前あり」とする。
  - 名前は前後の空白を除いて完全一致。シチュエーションは、フォルダ名も同じものを優先して対象にする（なければ、フォルダが違っても同じ名前の最初の1件）。
- 「同じ名前あり」の行には、印「同じ名前あり」と、その行の扱いを切り替えるボタンを出す：「上書きする」⇔「別件として追加」。**初期値は「上書きする」**。行のチェックは最初から入っている。
- 画面上部の件数の表示に「うち上書き N 件」を添える。追加ボタンの文言は「選んだ N 件を取り込む」に変える（上書きが含まれるため）。
- 「上書きする」で取り込むとき：
  - 既存の項目の `id`・`fav`・`uses`・`created` は残す。
  - `cat`・`tags`・`note` は、取り込む側が空なら既存のものを残す。シチュエーションの `folder`・`order` も、取り込む側にフォルダがなければ既存のものを残す。
  - それ以外の内容（本文、チップ、キャラ枠、性別など）は取り込む側で置き換える。要約（`text`）は `summary()` で作り直す。
  - ポジ・ネガ・表情を上書きしたときは、その項目を元にしているチップ（`pid` が同じもの）の `name`・`text`・`nl` も、編集画面で保存したときと同じように更新する。
  - 組み立てタブに読み込んでいる項目が上書きされ、未保存の変更がなければ、読み込み直す（編集画面で保存したときと同じ扱い。シチュエーションなら登録セリフも入れ直す）。未保存の変更があれば、組み立ての内容は変えない。
- 取り込み後のトースト：「N 件を取り込みました（うち上書き M 件）」。上書きが1件以上あるときは「元に戻す」を付け、押すと取り込み前の状態に戻る（`snapshot()` / `restoreSnap()` を使う。辞書も戻る）。
- 「別件として追加」のままなら、今までどおり同じ名前で2件目が増える。

## 4. バックアップの案内

- JSON バックアップを書き出したとき（`expo("json")`）、`S.cfg.lastBackup = Date.now()` を保存する。
- 設定画面の「データ」に1行追加：「最後のバックアップ：N 日前（YYYY/M/D）」。当日は「今日」、まだなければ「まだ取っていません」。
- 案内の帯（画面上部、既存の `#warn` とは別の要素 `#bkNote`。見た目は `.warn` に合わせる）を、次のどちらかのときに出す。
  - 一度もバックアップを取っておらず、登録が10件以上ある。
  - 最後のバックアップから14日以上たっていて、登録が1件以上ある。
- 帯の中身：「最後のバックアップから N 日たっています。」（未取得なら「まだバックアップを取っていません。」）＋「データはこの端末の中だけにあります。」＋ボタン「今すぐ保存」（JSON バックアップを書き出す）＋「あとで」。
- 「あとで」を押すと、3日間は出さない（`S.cfg.bkSnooze = Date.now()`）。「今すぐ保存」を押すと帯は消える。
- 帯は1行〜2行に収め、スマホで操作の邪魔にならない高さにする。ボタンは高さ36px以上。
- 帯の表示の判定は、起動時と、項目の追加・取り込み・バックアップの後に行う。

## 守ること（既存の動きを壊さない）

- `index.html` 1ファイルのまま。外部ライブラリを増やさない。編集するのは `index.html` と `README.md` だけ。
- 既存のコードの書き方に合わせる（`var` と `function`。アロー関数・テンプレート文字列・`let`/`const` は使わない。HTML に入れる文字列は必ず `esc()` を通す）。
- 既存の保存キーと JSON の形は変えない（`S.cfg` への項目の追加だけ。`normCfg` で読めるようにする）。
- コピーされる出力（出力欄・まとめてコピー・.txt・順番コピー）は1文字も変えない。
- 第2回までの操作（チップの操作パネル、長押しの並べ替え、スマホの一覧上部、順番コピー、貼り付けて取り込む、訳の辞書）がそのまま動くこと。
- 押せる部品は、スマホで高さ44px以上を目安にする（文中で指定したもの）。
- 色は既存の変数を使う。新しい色は増やさない。
- 文言は日本語、敬体、短く。既存の id と重複しないこと。

## 確認すること（実装者が自分で動かして確かめる）

Playwright と Chromium は入っている（`require('playwright')`、`chromium.launch()` にオプション不要。何もインストールしない）。テストのスクリプトはリポジトリに入れず、スクラッチ用のフォルダに置く。PC（1440×1000）とスマホ（`devices['iPhone 13']`）の両方で確かめ、`pageerror` を集め、スクリーンショットを撮って自分で見る。

1. 組み立ての3ブロックが開閉でき、閉じたときに要約が出る。見出し行の他のボタンは開閉せずに動く。再読み込みしても開閉の状態が残る。閉じたブロックに項目を追加すると要約の数が変わる。出力を閉じても順番コピーが動く。
2. スマホの編集画面が全画面で、見出し帯とボタン帯が固定され、長いシチュエーション（キャラ枠4つ）でも保存ボタンが常に見えて押せる。PC のモーダルでもボタンが常に見える。
3. キャラ枠が3つ以上のシチュエーションを編集で開くと、枠が閉じた状態で要約が出る。開閉でき、閉じたまま保存しても枠の内容（状態・表情・セリフ・性別・吹き出し）が失われない。
4. 「Muse 用にコピー」が登録済みの項目の編集のときだけ出る。コピーされた文の JSON 部分を取り出して `JSON.parse` でき、`id`・`cid` などが入っておらず、訳のあるタグに `ja` が付いている。
5. 4 の JSON の中身を少し変えたもの（同じ名前）を貼り付けて取り込むと、「同じ名前あり」「上書きする」が出て、取り込むと件数は増えず内容が置き換わる。`fav`・`uses` が残る。「元に戻す」で元の内容に戻る。
6. 「別件として追加」に切り替えると、同じ名前で2件目が増える。
7. 組み立てに読み込んでいるシチュエーションを上書きすると、未保存の変更がなければ組み立ての内容も新しくなる。未保存の変更があれば組み立ては変わらない。
8. ポジの項目を上書きすると、それを元にしたチップの表示と出力が新しい本文になる。
9. バックアップの案内：10件以上で未取得のとき帯が出る。「あとで」で消え、再読み込みしても出ない。「今すぐ保存」で JSON が書き出され、帯が消え、設定画面に「今日」と出る。`lastBackup` を15日前にすると帯が出る。
10. これまでの機能が壊れていない。次の既存スクリプトが `errs []` で終わること（スマホの古いセレクタで落ちるものは、原因を確かめて報告する）：スクラッチの `v2.js` `v3.js` `t26.js` `t24.js` `t23.js` `t20.js` `t15.js` `t12.js`。`pageerror` が出ない。PC とスマホのスクリーンショットで崩れがない。id の重複がない。
